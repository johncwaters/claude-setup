Section 1

What the workflow does

Inputs: a dirty git worktree. Job: sync the integration branch, clean AI slop, review the diff, block on critical or high findings, generate a conventional commit message with trailers, stage, commit. Output: a commit plus a report. Safety boundary: never push, never bypass hooks. It is repeated because every feature or fix across card-harbor, glissa, keeplings, and milepost ends with /commit.

Why this workflow, not another

Five candidate workflows from the same session history were compared before selecting /commit for compilation. Totals below cover all historical runs of each workflow, not just the 13 benchmark scenarios.

Both sides use provider usage events, not estimates. The old side includes subagent transcripts attributed by session and time-window overlap. The new side includes the claude -p wrapper's system-prompt overhead, roughly 42,000 tokens per call, counted against the compiled side honestly rather than netted out. This overhead is also why non-cached tokens rise on 3 of the 13 scenarios (1eb5432 +237.1%, 688d467 +22.2%, c468d9f +28.6%): when the historical run's own non-cached usage was already small, three fresh, uncached claude -p invocations can non-cache more tokens than the historical run did, even though gross tokens still fall sharply on every scenario.

Data coverage

103 sessions and 327 subagent transcripts analyzed, from Claude Code session jsonl (v2.1.x); one Codex CLI session was excluded. Date range 2026-07-19 to 2026-07-24 (5 days; the only history that exists, lookback config was 30 days). Prompts, outputs, and tool call inputs are complete; model names, input/output/cached token fields are available. External side effects (git/gh commands) are partially recorded, visible only in bash tool inputs. Gaps: no per-request latency field, so elapsed time is derived from event timestamps; 4 committed historical episodes could not be resolved to surviving repos; 2 episodes (b7403ba, 24,447s; fb6a080, 24,686s) have idle-inflated, overnight durations and were excluded from scenario selection in favor of scenarios with active-session durations.

Failures during development, disclosed

The first benchmark run hit 2 argv-limit crashes (WinError 206 on Windows) and 4 empty reviews (max-turns tool cutoff, hook-induced nonzero exits). Both were fixed in iteration 2 (utf-8 decoding and the review severity rubric), which was then rerun. Two iterations total, the iteration cap. Some tokens from the earlier failed attempts were partially overwritten by the reruns on disk, so benchmark-side failed usage is partially unmetered; final-run usage, the numbers reported throughout this document, is complete.

Use it now

Demo it VERIFIED

From C:\Users\johnw\Projects\compiled-commit:

python bench\run_bench.py --ids 1eb5432 --replay-llm --fixtures bench\fixtures --out %TEMP%\cc-demo

Zero LLM calls, zero cost. Replays recorded fixtures against a temp clone; the terminal state COMMITTED exists only inside that temp clone. Verified: 0.76s.

Use it VERIFIED

From C:\Users\johnw\Projects\compiled-commit:

python runner.py --repo <your-repo> --dry-run --no-sync --skip-deslop --json

Live sonnet review and message generation on the real dirty worktree, no writes of any kind: --dry-run skips the commit, --skip-deslop prevents patch application to your live tree. Verified today against card-harbor with real uncommitted changes: DRY_RUN_OK, message generated after one validation retry. The full pipeline, including slop patching and an actual commit (run without --dry-run --skip-deslop), is exercised end to end only in temp-clone replay, so that path is labeled NOT LIVE-VERIFIED below.

Install it NOT EXECUTED, REQUIRES APPROVAL

Replace ~/.claude/commands/commit.md with a thin activation instruction that runs:

python C:\Users\johnw\Projects\compiled-commit\runner.py --repo <cwd> --json

and relays the typed result without re-taking control of selection, validation, or side effects. Keep the flag mapping: --no-sync, --skip-deslop, --skip-review, message passthrough. Nothing was installed, committed, pushed, or activated as part of producing this report.

Section 9

Installation decision

Recommend: use as an isolated prototype now, dry-run mode is immediately useful, and promote it to the default /commit only after (a) a few supervised live commits and (b) a decision on the message why-context gap.

Mitigation option for the gap: pass an optional --context "one line of intent" argument into the commit_message call; it costs nothing when omitted.

Maintenance: about 1,700 lines of stdlib Python, no dependencies; the main risk is claude CLI flag drift.

Unverified: live slop patching, live sync against origin, and the hook-failure path on real hooks.

Approval needed: replacing commit.md is an explicit user action, not taken as part of producing this report.

Data sources: bench/scenarios.json, bench/results/*.json (including summary.json and judge.json), and the compilation's own report_data.json. All figures are provider-reported token usage; none are estimated or extrapolated beyond the rounding shown.
